## 代码审查中修复的问题

1. 生产运行时补齐原子 job ID 所有权、完整定义幂等、受限重试、崩溃恢复、主动取消、哈希检查点和所有权令牌锁；旧持有者不能误删被替换的锁。
2. 生产处理器增加正式 JSON Schema、固定白名单、逐处理器参数合同和 `--workspace` 输出根；输出父路径及已有目录树中的符号链接均阻断。
3. Blender 统一使用无 shell、限时、限输出执行器；相机 ID、场景/批准绑定和检查点均绑定当前计划与产物哈希，陈旧检查点必须重渲染。
4. OCR、增量再生成和本地转换器统一容量、超时和输出上限；需要批准的执行路径不能被普通作业定义绕过。
5. 图片、CAD/PDF/BIM、点云、目录和已有 3D 输入增加常规非符号链接文件、容量/数量上限、变化检测；视觉重建只上传与证据 SHA-256 一致的单次读取图片。
6. RealmRouter 增加提示词/图片/响应大小、超时/重试、公共 HTTPS 下载、DNS/私网阻断、禁止重定向和 PNG/JPEG/WebP 魔数验证，错误信息不回显凭据。
7. GLB 外部纹理限制在纹理根目录，限制数量和单文件/总容量，验证 KTX2 签名；Viewer 拒绝隐藏文件、穿越和符号链接并使用限制性安全头。
8. 迁移默认 dry-run，旧运行时一律进入 `blocked/review_required`，拒绝敏感参数和非法 ID；Spatial JSON 与批准文件仍禁止自动迁移。
9. 交付清单绑定准确批准链、来源、信任根、资产许可证、限制及显式产物，验证真实项目所用源清单与交付绑定一致。
10. 资格包不再接受手写摘要：必须内嵌完整平台记录、目标报告/原始捕获和真实项目接受记录，并逐层复算哈希、预算与最终提交绑定。
11. 为避免提交与证据循环，资格包保存在忽略目录并通过受保护 Base64 secret 进入实际标签工作流；真实项目接受要求干净工作树和准确 `HEAD`。
12. 许可证审计覆盖全部 40 个锁定组件及有效 SRI；8 个工作流 action/可复用工作流固定完整 SHA。SBOM 使用唯一组件引用、正确 scoped npm PURL 和依赖图；发布验证复算 SHA-256、npm SHA-1/SHA-512 并核对 SBOM 身份。
13. `sharp 0.34.3` 和 `ajv 8.17.1` 命中上游安全公告；已升级到修复版本 `sharp 0.35.3` 与 `ajv 8.18.0`，依赖审计归零。
